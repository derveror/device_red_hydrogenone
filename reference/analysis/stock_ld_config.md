# Stock Android 8.1 linker namespace analysis

Source: supplied `/system/etc/ld.config.txt`.

## Confirmed
- `[system] namespace.default.isolated = false`
- `[vendor] namespace.default.isolated = false`
- system default namespace searches both `/system/${LIB}` and `/vendor/${LIB}`
- vendor default namespace searches vendor paths **and** `/system/${LIB}`
- only the dedicated `sphal`, `rs`, and `vndk` namespaces are isolated

This is an early Treble/O-MR1 configuration, not a clean cross-version vendor boundary.
The H1 proprietary vendor therefore cannot be expected to run unchanged against Android 15
system libraries.

## LOS 22.2 strategy
Do **not** ship the stock `ld.config.txt`.
Use the modern linker configuration generated by Android 15 and patch legacy proprietary
ELF dependencies.  For O-era HIDL clients use Lineage's `libhidlbase-v32` vendor variant,
following current maintained legacy-device trees.  Keep the supplied 32/64-bit stock
`libhidlbase`, `libhidltransport`, and `libhwbinder` only as ABI/symbol references while
debugging; they are not copied into the final vendor image.
